# 역할별 서브에이전트 분업 구조 (모델 무관)

근거: 2026-07 세션에서 실제 운용한 편성 — 생성 에이전트 2종(b2d-api 등),
검수 에이전트 3회(3-렌즈 QA, qa-realestate, qa-phase234), 포크 4회
(인수인계·논문·운영문서). 전부 충돌 0으로 완주.

## 1. 생성/검수 분리 (불변 원칙)

- 만든 주체는 자기 산출물의 완료 판정을 내리지 못한다. 독립 검수자가
  **생성자 코드를 참조하지 않고 원본에서 재계산**해 대조한다.
- 실효 증명: 검수가 잡은 것 — API 키 노출(HIGH), 사전인증 무제한 DB 조회
  (MED), 환각 좌표 [0,0](MED). 전부 생성 직후 자체 점검을 통과했던 것들.
- 검수 사양은 VERIFIER_SUBAGENT_SPEC.md 참조.

## 2. 파일 소유권 사전 분할 (충돌 회피)

- 병렬 작업 전, 파일 단위로 소유자를 선언한다. 실례: Phase 4 병렬 시
  "메인 = internal/geocode·places, 에이전트 = internal/auth·meter +
  server.go **배선만** (핸들러 로직 불가침)" — 같은 파일을 만져야 하면
  구역(배선 vs 핸들러)으로 쪼갠다.
- 소유권 밖 발견 사항은 수정하지 말고 보고로 넘긴다 (에이전트가 places
  10초 행을 발견하고도 고치지 않고 "flag to engine"으로 보고한 사례).

## 3. 포크 vs 일반 에이전트 선택 기준

| | 포크 (컨텍스트 상속) | 일반 에이전트 |
|---|---|---|
| 컨텍스트 | 세션 전체 기억 보유 | 백지 — 지시문이 전부 |
| 적합 작업 | 세션 지식 증류 (인수인계, 논문, 감사, 회고) | 사양이 문서화된 독립 구현 (Phase 4 미들웨어) |
| 지시 비용 | 낮음 (맥락 설명 불요) | 높음 — **필독 파일 목록**과 완료 기준을 지시문에 박아야 함 |
| 주의 | 상속 컨텍스트만큼 무겁다 | 세션 관례를 모름 — 관례 문서 포인터 필수 |

## 4. 에이전트 보고의 메인 재검증 의무

- 검수자도 틀린다. 실례: QA가 "set_limit tx 무의미"(INFO-1)라 판정했으나
  실제로는 tx가 커넥션 고정 역할 — 메인이 재검증해 기각하고 주석으로 응답.
- 규칙: 에이전트 보고는 심각도 높은 항목부터 메인이 근거를 직접 확인한
  뒤 반영한다. 반영/기각 사유를 로그에 남긴다.

## 5. 통신 규약

- 에이전트 보고 형식: 변경 파일 목록 + 실측 검증 결과 + 미해결/발견 플래그.
- 커밋은 메인이 일괄 (에이전트 커밋 금지) — 검수·재검증이 커밋 앞에 온다.
- 유휴 통지는 신호가 아니다 — 보고서가 없으면 보고를 요청한다.
