# 검수자 서브에이전트 표준 사양 (VERIFIER SPEC)

작성 2026-07-12. 이 세션에서 실전 운용한 검증 에이전트 3회
(bridge_converter 3-렌즈 QA / qa-realestate / qa-phase234)의 실무를 증류한
표준. 생성/검증 분리 원칙(최상위 지시서)의 구체 절차다.

## 1. 원칙 (불변)

1. **독립 재계산.** 생성자의 코드를 읽고 로직을 따라가며 "맞다"고 판정하지
   말 것. 원본 데이터에서 결과를 **독립적으로 다시 계산**해 산출물과
   대조한다. (사례: 3-렌즈 QA는 converter를 참조하지 않고 원본 zip에서
   754,992 박스를 재계산 — 최대편차 5.0×10⁻⁷ 확인)
2. **실 DB·실 호출 대조 허용.** 정적 분석에 그치지 말고 docker exec psql,
   curl 실호출로 라이브 검증한다. (사례: qa-realestate가 (bcode,jibun)
   중복 9,614쌍을 실 DB에서 셌다)
3. **코드 수정 금지.** 보고만 한다. 수정은 메인(생성 책임자)의 몫 —
   검수자가 고치면 생성/검증 분리가 무너진다.
4. **검수자도 틀린다 — 메인이 재검증한다.** (사례: qa-phase234의 INFO-1은
   set_limit이 "backend-static이라 tx 무의미"라 했으나, 실제로는 커넥션
   단위 설정이라 tx의 커넥션 고정이 핵심 기능이었다. 메인이 반박 근거를
   주석으로 남기고 tx를 유지했다.) 검수 보고는 입력이지 판결이 아니다.
5. **심각도 정직.** 발견 없으면 "이상 없음 + 확인 범위"를 명시. 발견을
   부풀리지도 뭉개지도 말 것.

## 2. 입력 (메인이 검수자에게 제공)

- 대상: 커밋 해시 또는 미커밋 working tree (git diff 범위 명시)
- 파일 목록 + 각 파일의 역할 1줄
- 검증 관점 목록 (아래 §3에서 해당 항목 선택)
- 실 DB 접속 경로 (docker exec b2d_postgis psql -U b2d -d b2d_geo)
- 명시적 금지: 코드 수정, 커밋, 메인 동시 작업 파일 접촉

## 3. 필수 관점 체크리스트 (프로젝트 표준)

| # | 관점 | 확인 방법 |
|---|---|---|
| 1 | SQL 인젝션 | 전 쿼리 $n 바인딩/CopyFrom — 문자열 조합 grep |
| 2 | 멱등성 | upsert/delete+insert 재실행 시 행수 불변, 트랜잭션 경계 |
| 3 | 좌표계 | SRID 변환 경로, bbox 실측 대조 (실좌표 표본) |
| 4 | 인코딩 | CP949/UTF-8 — 한글 필드 실디코드, .cpg 불신 |
| 5 | 지시서 준수 | 사실 반환만 — score/weight/adjust/보정 패턴 grep |
| 6 | 성능 실측 | 신규 쿼리 EXPLAIN ANALYZE (2.7M~13M 행 테이블 기준) |
| 7 | 시크릿 | .env gitignore, 하드코딩 키, 에러 메시지 키 노출 |
| 8 | 스키마 verbatim | 마이그레이션 vs 지시서 원문 대조, 추가분 근거 확인 |
| 9 | 경계값 | 빈 입력/퇴화 도형/0면적/중복 키 — 원본에서 실물 탐색 |
| 10 | 문서-실물 일치 | openapi/dataspec의 주장 vs 실응답 표본 대조 |

## 4. 보고 형식

```
심각도 등급: CRITICAL / HIGH / MED / LOW / INFO
각 발견: [등급] 파일:줄 — 문제 1문장. FIX: 수정안 1줄.
PASS 항목: 관점별 "확인 방법 + 결과" 1줄씩 (무엇을 어떻게 봤는지)
범위 주의: 검증하지 않은 것 명시 (N/A 사유 포함)
BOTTOM LINE: 머지 가능 여부 + 선결 조건
```

## 5. 메인의 후처리 규약

- CRITICAL/HIGH: 즉시 수정 후 재검증 요청
- MED: 커밋 전 수정 (사유 명시하고 보류 가능)
- LOW/INFO: 수정 또는 todo에 근거와 함께 기록 (침묵 금지)
- 검수 발견을 반박할 때는 **실측 근거**를 남긴다 (주석/로그) — 사례 §1.4
