# 문서·PDF·표 분석 절차 (DOCUMENT ANALYSIS WORKFLOW — 모델 무관)

목적: 외부 파일 명세서·데이터 파일·PDF·표를 분석해 dataspec으로 남기는
표준 절차. 원칙은 하나 — **메타데이터를 믿지 말고 실물에서 측정**한다
(SYSTEM_PROMPT_V2 §2). 산출은 docs/dataspec/<이름>.md.

## 1. 인코딩 실측 (첫 단계)

- 선언된 인코딩을 믿지 말고 **디코드 시험으로 실측**한다. 한글 필드가
  mojibake면 CP949로 재시도. .cpg가 UTF-8이라 써 있어도 실제는 CP949인
  선례가 있다 — .cpg 불신.
- 판별 방법: 대표 행 몇 개를 UTF-8/CP949 각각으로 디코드해 육안 대조.
  확정 인코딩을 dataspec에 명기한다.

## 2. 구조 파싱 — 헤더

- 스키마는 문서 표가 아니라 **파일 헤더를 파싱**해 확정한다. 컬럼 수·순서·
  구분자·따옴표 규칙을 실물에서 읽는다.
- 행수는 원본에서 직접 센다. rows=정확히 1,000,000이면 잘림 신호 —
  대형 시도 분할 배포(_02…) 조각 존재를 확인한다.

## 3. 좌표계 확정 (공간 데이터)

- .prj가 있으면 읽고, **없으면 bbox 수치로 EPSG를 판별**한다 (한국이면
  EPSG:5179/5186/4326 등 좌표 범위로 역추정). 문서의 좌표계 주장은
  bbox 실측으로 대조한 뒤 채택한다.

## 4. 표본 대조

- 파싱 결과가 원본과 맞는지 **대표 표본 3~5건을 실물과 대조**한다 (실주소·
  실필지·실좌표). 파싱이 조용히 어긋나면 카운트로는 안 잡힌다.

## 5. dataspec 기록

- 확정한 인코딩·스키마·좌표계·행수·**함정**을 dataspec에 남긴다. 함정은
  재현 신호와 함께 ("rows=정확히 1,000,000이면 잘린 파일"). 기존 6종 참조.

## PDF — 텍스트 추출 실패 대비

1. 먼저 텍스트 레이어 추출을 시도 (pdftotext / 라이브러리). 표 구조가
   깨지면 레이아웃 보존 모드로 재시도.
2. 스캔본이라 텍스트가 없으면 **페이지를 이미지로 렌더해 직접 판독**한다
   (읽기 도구의 이미지·PDF 페이지 렌더 사용). 표는 페이지 단위로 나눠 본다.
3. 추출값은 반드시 원문 페이지와 표본 대조 — OCR/추출은 조용히 숫자를
   바꾼다. 추출 실패·불확실 셀은 dataspec에 "미확인"으로 정직히 남긴다.

## 게이트웨이·API 응답 함정

- 공공 게이트웨이(data.go.kr)는 기본 UA를 WAF가 차단("Request Blocked") —
  Mozilla UA 명시. 일부 API(juso ADS)는 결과를 body가 아니라 HTTP 헤더에
  실어 보낸다 — `curl -D -`로 헤더까지 확인.
