# 긴 대화 분리 기준 (모델 무관)

근거: 2026-07-05~12 단일 세션 8일 운영 실례 — 두 프로젝트(교량 탐지,
주소 API) + 취업 상담 + 투자자 응대까지 한 세션에서 처리한 극단 사례의
득실을 사후 평가해 기준으로 만든다.

## 단일 세션 유지가 이득인 조건

1. **살아있는 이벤트가 있다** — 백그라운드 학습·적재·감시는 세션에
   묶인다. 세션을 끊으면 완료 통지를 받을 주체가 사라진다. 이 세션이
   8일을 간 1차 이유 (학습 완주 대기 → 자동 시퀀스).
2. **컨텍스트가 자산이다** — 포크가 세션 기억만으로 인수인계·논문·감사
   문서를 즉시 생산했다. 백지 세션이었으면 각각 리서치부터 다시.
3. **위임·관례가 누적돼 있다** — 자율 범위, 검증 관례, 함정 지식이
   대화에 살아 있어 지시 비용이 계속 떨어진다.

## 분리해야 하는 조건

1. **트랙이 컨텍스트를 공유하지 않는다** — 이 세션의 취업 상담·투자자
   DM은 개발 컨텍스트와 무관했고, 개발 지식이 쓰인 순간(아티팩트 링크)을
   빼면 별도 세션이 맞았다. 민감·개인 주제는 특히 분리 권장.
4. **이벤트가 없다** — 예약 큐가 소진되고 순수 신규 작업이면 새 세션이
   깨끗하다. 단, 시작 전 인수인계 문서 포인터를 반드시 주입.
3. **사용량 압박** — 긴 세션은 요약을 거치며 세부가 마모되고, 매 턴
   비용이 커진다. 이 세션도 80% 시점부터 압축 운영으로 전환했다.

## 이 세션(8일)의 사후 평가

- 득: 학습 3회·적재 5회의 이벤트 연속성, 포크 문서 4종의 즉시 생산,
  함정 17종의 맥락 보존 — 분리했으면 대부분 재구축 비용 발생.
- 실: 취업·투자 상담이 개발 기록에 섞임(회고 시 노이즈), 사용량 가속,
  요약 후 세부 소실 위험 상시 존재.
- 결론: **"이벤트 + 공유 컨텍스트"가 있으면 유지, 없으면 분리**가 기준.
  주제 혼입은 예외적 허용이었지 모범이 아니다.

## 분리 시 필수 절차

새 세션 첫 메시지에: ① 인수인계 문서 경로 (POST_FABLE_HANDOFF.md)
② 위임 선언 ③ 검증 요구 — 템플릿은 ONE_PAGE_AI_WORKFLOW_MANUAL.md.
