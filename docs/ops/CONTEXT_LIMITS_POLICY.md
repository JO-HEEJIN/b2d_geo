# 컨텍스트 한계 운영 기준 (모델 무관)

전제: 긴 세션은 반드시 요약(compaction)을 거친다. 요약은 손실 압축이다.
따라서 운영 원칙은 하나로 수렴한다 — **진실은 repo에, 대화는 캐시로.**

## 원칙 1 — repo가 원본, 대화는 캐시

- 결정·수치·함정·상태는 발생 즉시 repo 문서로 방출한다:
  tasks/todo.md(상태), learning_log.md(서사), docs/dataspec/(명세),
  docs/ops/(규칙), 커밋 메시지(검증 수치).
- 검증: 이 세션은 8일간 여러 번 요약을 거쳤지만 작업 연속성이 유지됐다 —
  매 단계가 문서·커밋으로 착지해 있었기 때문. "대화에만 있는 지식"은
  요약 한 번이면 소멸한다고 가정하라.

## 원칙 2 — 대용량 출력은 컨텍스트에 넣지 않는다

- 장시간 명령은 백그라운드 태스크로 — 출력은 파일로 떨어지고, 대화에는
  grep/tail 발췌만 가져온다. (512KB 초과 파일은 통짜 Read가 거부된 실례 —
  애초에 통짜로 읽을 일을 만들지 않는다.)
- 진행 로그(프로그레스 바)는 필터로 제거하고 판정 신호만 남긴다.

## 원칙 3 — 무거운 소화는 포크에 위임

- 대량 파일 탐색, 장문 작성, 감사는 컨텍스트 상속 포크가 수행하고
  **요약만** 반환받는다 (스킬 감사 89만 토큰을 포크가 소화하고 메인은
  통계 5줄만 수신한 실례).
- 메인 컨텍스트는 판단·조율 전용으로 아낀다.

## 원칙 4 — 사용량 압박 시 행동 전환 (실전 단계)

80% 시점 (이 세션 실제 전환점):
- 응답 압축 모드 강화, 신규 대형 탐색 자제
- 우선순위 재정렬: 판단 밀도 높은 작업 먼저 (기계적 작업은 후임에게)
- **지식 방출 가속**: 남은 용량을 "대화 속 지식 → repo 문서화"에 투자
  (ops 문서 스위트가 그 산물)

90%+ 시점:
- 신규 작업 수주 중단, 마감 절차(AUTONOMOUS_COMPLETION_RULE.md) 실행
- 인수인계 문서 최종 갱신 → 다음 세션이 백지에서 시작하지 않게

## 요약 직후 자가 점검

요약을 거쳤다고 감지되면: todo.md와 최근 커밋 로그를 다시 읽어 현재
상태를 repo 기준으로 재동기화한다. 대화 기억과 repo가 충돌하면 repo가 이긴다.
