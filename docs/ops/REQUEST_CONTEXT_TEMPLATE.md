# 요청 배경 템플릿 (REQUEST CONTEXT — 사용자용, 모델 무관)

목적: 사용자가 새 작업을 요청할 때 **채워 주면 좋은 배경**. 필수는 아니지만,
이 다섯을 주면 모델이 되묻지 않고 바로 독립 루프에 들어간다. 안 주면
모델이 가정을 명시하고 진행하되, 오판 비용이 큰 결정은 되묻는다.

## 채우면 좋은 5요소

1. **목표** — 무엇을 이루려는가 (결과물 형태까지). "지오코더 정확도를
   전국으로 확장" 같은 한 줄. 왜 필요한지(why) 한 줄을 덧붙이면 모델이
   트레이드오프를 스스로 판단한다.
2. **마감 / 예산** — 시간 데드라인과 비용 상한. 급하면 "4분 데드라인"처럼
   명시 (긴 리서치 하니스가 데드라인과 충돌해 폐기된 선례 — 시간이 짧으면
   모델이 수동 경로를 고른다). 클라우드 지출 상한도 여기에.
3. **기존 시도** — 이미 해본 것과 실패한 것. "V-World 대형 시도 분할 배포로
   받았는데 rows가 딱 100만이라 의심된다" 같은 단서 하나가 진단을 크게
   줄인다. 관련 파일·커밋·로그 경로가 있으면 함께.
4. **성공 판정** — 무엇을 보면 "됐다"인가. 검증 가능한 조건으로: "하남시청
   좌표가 실위치와 맞으면", "행수=원본이면", "테스트 green이면". 판정을
   주면 모델이 그 기준으로 하니스를 짜고 스스로 루프를 돈다.
5. **건드리면 안 되는 것** — 손대면 안 되는 파일·데이터·설정, 비가역 경계
   (프로덕션 DB, 원격 인스턴스 종료, 공개/퍼블리시). 절대 규칙에 걸리는
   것이 있으면 미리.

## 붙여도 되는 것 / 확인 사항

- **API 키·시크릿은 채팅에 붙여도 된다** — 모델이 .env로 옮기고 원문
  재출력을 하지 않는다 (DATA_RETENTION_AND_PRIVACY_RULES). 다만 붙였다는
  사실은 남으니, 운영 전 해당 키 revoke를 권할 수 있다.
- **위임 범위를 한 번 선언**해 두면 매 작업 되묻지 않는다: "가역 작업(코드·
  커밋·푸시·잔액 내 클라우드)은 실행 후 보고, 잔액 초과 과금·비가역만 확인".

## 최소형 (급할 때)

> [목표 한 줄]. [됐다고 볼 조건]. [건드리면 안 되는 것]. 나머지는 알아서,
> 가역이면 실행 후 보고.
