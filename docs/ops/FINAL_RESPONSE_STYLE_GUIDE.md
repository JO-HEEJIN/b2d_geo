# 최종 보고 스타일 (FINAL RESPONSE STYLE — 모델 무관)

목적: 세션·작업 종료 보고의 형식. 사용자는 보고만 읽는다 — 결론이 먼저,
근거는 뒤, 실패는 정직하게. 신뢰하되 검증(ONE_PAGE_AI_WORKFLOW_MANUAL)의
사용자 측 스팟체크가 통하도록 쓴다.

## 1. 결론 선행

- 첫 문장이 "무엇을 했는가 / 무엇을 찾았는가"에 답한다. 사용자가 "TLDR만"
  이라 물었을 때 나올 그 문장을 맨 앞에. 과정·근거는 그 뒤 문단에.
- 마지막 문단이 계획·질문·"이제 ~하겠습니다"면 그건 보고가 아니다 —
  그 작업을 지금 끝내고 결과를 보고한다.

## 2. 표는 열거 사실만

- 표는 **열거 가능한 사실**(Phase별 상태, 함정 목록, 파일 경로+역할)에만
  쓴다. 설명·서사는 표 밖 산문으로. 표 칸에 문장을 우겨넣지 않는다.
- 수치는 출처를 답할 수 있게 (하니스 경로/로그/EXPLAIN). "그 수치 어디서
  나왔어?"에 답 못 하면 아직 보고할 단계가 아니다.

## 3. 실패·미해결 정직 명기

- **완료 보고에 실패·미해결이 0이면 오히려 의심**받는다. 정직한 보고에는
  보통 "알려진 이슈" 절이 있다 (Phase 6 감사 대상 4건처럼).
- 건너뛴 단계는 건너뛰었다고, 테스트가 깨지면 출력과 함께 쓴다. 검증된
  완료만 담담히 "완료"라 부른다 — 확인 안 한 것에 완료를 붙이지 않는다.
- 검수자 발견을 반박했다면 실측 근거를 함께 남긴다 (검증의 검증).

## 4. 다음 액션 구분 (자동 / 사용자)

- 남은 일을 **모델이 자동으로 할 것**과 **사용자만 할 수 있는 것**으로
  나눠 명시한다.
- 사용자 몫: 브라우저 작업(정부 포털 다운로드·신청, 계정 인증, 결제·충전),
  결정(잔액 초과 지출·공개·비가역 삭제·논문 저자/투고), 키 전달.
- 자동 몫: 가역 작업(코드·커밋·푸시·잔액 내 클라우드)은 위임 범위 내에서
  실행 후 보고한다 — 이걸 "해도 될까요?"로 묻지 않는다.

## 5. 세션 마감 보고 골격

> **결론**: [이번 세션에 닫은 것 한 줄].
> **한 것**: [Phase/항목별 검증 수치와 함께, 표 가능].
> **알려진 이슈**: [미해결·실패, 재현 신호와 함께].
> **가동 중 자원**: [켜둔 서버·감시·과금 자원 — 없으면 "없음" 명시].
> **다음**: 자동 = [모델이 이어서 할 것] / 사용자 = [브라우저·결정·키].
