# 멈추고 물어야 할 경계 (모델 무관)

원칙: 위임은 "가역 작업 전부"에 대한 것이다. 아래 4범주만 사용자 확인을
기다린다 — 나머지를 물어보는 것은 위임 위반이다.
근거 사례는 전부 2026-07-05~12 실전 세션.

## 반드시 멈추고 묻는 것 4범주

1. **잔액·한도 초과 지출**
   - 실례 1: 2차 학습 예산 재계산 결과 잔액 $8.18 < 잔여 $9.4 전망 →
     "충전 vs epoch 8 조기중단" 두 옵션과 수치를 제시하고 대기.
   - 실례 2: 마지막 2 epoch 마진 $0.11 → "$3 충전하면 안전" 제시, 사용자
     충전 후 진행. **수치와 대안 없이 "돈 더 필요해요"만 던지는 것 금지.**
2. **비가역 삭제·파괴**
   - 실례: rm -rf가 훅에 막히자 우회 삭제 대신 job tmp로 이동(비파괴 대체).
   - 실례: 원본 zip 27GB 삭제는 절감 효과를 보고하되 실행은 사용자 결정에
     맡김 — 사용자가 "지우란 뜻 아니었다"고 답한 사례가 이 규칙의 근거.
   - 원격 자원 파괴(pod 종료)는 회수+체크섬 완료가 확인된 경우만 자율 실행.
3. **외부 공개(퍼블리시)**
   - 실례: 공개 gist는 내용이 전부 공공데이터임을 확인하고도 "올려" 승인
     후에만 발행. 사설 repo 푸시는 위임 범위, 공개 전환은 아님.
4. **계정·인증·결제 행위**
   - 브라우저 로그인, OAuth scope 승인(gh auth refresh), 정부 포털 신청,
     충전 — 전부 사용자 손. 모델은 정확한 명령/URL/절차만 준비해 건넨다.

## 묻지 말아야 할 것 (물어보면 위임 위반)

- 버그 수정, 리팩터 없는 코드 추가, 테스트 작성
- 학습·적재 재시작, config 조정, 서버 재기동
- 커밋·푸시 (위임 선언 이후), 문서·로그 갱신
- 잔액 내 클라우드 자원 생성·조작
- 검증 하니스 실행, 에이전트 스폰

## 경계 판정이 애매할 때

"되돌릴 수 있는가 + 돈이 나가는가 + 밖으로 나가는가" 3문. 셋 다 아니오면
실행 후 보고. 하나라도 예면 수치·대안과 함께 질문 1회로 압축.
