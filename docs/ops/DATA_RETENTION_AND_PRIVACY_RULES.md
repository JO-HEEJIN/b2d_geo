# 민감정보·데이터 취급 기준 (DATA RETENTION & PRIVACY — 모델 무관)

목적: 키·시크릿·개인정보·공공데이터의 취급 경계. 절대 규칙(데이터 출처
화이트리스트)과 함께 읽는다. 원칙: 시크릿은 한곳(.env)에만, 공개는 사용자
승인 후에만, 개인정보는 목적 밖으로 나가지 않게.

## 1. API 키·시크릿 — .env 전용

- 모든 키는 **.env에만** 둔다. gitignore에 포함됐는지 확인한 뒤 기록한다.
- **원문 재출력 금지** — 채팅·커밋·로그·에러 메시지에 평문 키를 다시 찍지
  않는다. 참조는 변수명으로만(MOLIT_API_KEY, REB_API_KEY, JUSO_API_KEY).
- 코드에 하드코딩 금지. 업스트림 에러는 redact 후 로그만 남기고, 에러
  응답에 내부 정보·키를 노출하지 않는다.

## 2. 채팅에 온 키 처리 절차

사용자가 채팅에 키를 붙이는 것은 허용된다. 받으면 순서대로:

1. **.env로 옮긴다** (gitignore 확인 후). 코드는 env에서 읽게 배선.
2. **원문을 재출력하지 않는다** — 이후 대화에서 변수명으로만 지칭.
3. 채팅/transcript에는 평문이 남는다는 사실을 알린다. **운영 전 revoke +
   신규 발급을 권한다** (harness 테스트 키가 transcript에 노출된 선례 —
   `apikey create`로 신규 발급, 기존 키 revoke).

## 3. 공개 전 사용자 승인

- 외부로 나가는 모든 행위(퍼블리시, 저장소 공개, 메일 발송, 외부 서비스
  업로드)는 **사용자 승인 후에만**. 한 번 나간 것은 캐시·색인되어 삭제해도
  남을 수 있다.
- 비가역·외부 노출 작업은 위임 범위 밖 — 가역 작업만 실행 후 보고, 이건
  물어본다 (SYSTEM_PROMPT_V2 §5).

## 4. 공공데이터 vs 개인정보 구분

- **공공데이터**(정부·공공 공식 채널, 화이트리스트 통과분)는 라이선스
  실물 확인 후 자유 사용 — 단 신규 소스는 라이선스 확인 필수
  (dacl10k CC BY-NC 배제 선례).
- **개인정보**는 다르다. 주소·좌표·필지 같은 위치 데이터라도 특정 개인과
  결합되면 개인정보 — 수집 목적(지오코딩·검색) 밖으로 재사용·외부 전송
  하지 않는다. 감정평가 절대 경계도 여기 걸린다: 사실 반환만, score/weight/
  adjust/보정/추천 금지.

## 5. 보존·정리

- 원격 볼륨은 인스턴스와 함께 소멸 — 종료 전 회수 + 체크섬. 반대로 회수한
  체크포인트·로그에 시크릿이 섞이지 않았는지 확인한다.
- 로그·transcript에 남은 민감정보는 세션 마감 시 점검 항목에 포함한다.
