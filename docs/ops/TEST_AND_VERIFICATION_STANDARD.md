# 검증 표준 (TEST & VERIFICATION STANDARD — 모델 무관)

목적: "동작한다"를 "수치가 있는 검증 통과"로 바꾸는 표준. 측정이 완성을
정의한다 (SYSTEM_PROMPT_V2 §1). 기능 종류별로 아래 층위를 골라 적용하되,
핵심 산출물은 다층을 겹친다. 독립 검수는 VERIFIER_SUBAGENT_SPEC 참조.

## 1. 단위 테스트 — 설계 표 케이스

- 로직에 설계 문서가 있으면 그 **표의 모든 케이스 + 엣지 케이스**를
  테스트로 옮긴다 (주소 파서: 설계 표 11케이스 + 엣지 4종 전부 통과 선례).
- 경계값을 반드시 포함: 빈 입력, 퇴화 도형, 0면적, 중복 키. 원본 데이터에서
  실물 경계값을 찾아 넣는다 (합성 케이스만으로는 실결함을 못 잡는다).

## 2. 정확도 하니스 — 대표 N × 변형

- 정확도가 중요한 기능은 **대표 입력 N건 × 여러 변형**의 하니스를 먼저
  설계하고, 그 수치로만 완성을 말한다. 대표 케이스 수동 확인은 완성이 아니다.
- 표준 선례: 지오코더 = 실주소 200건 × 4변형(원문/시도생략/축약/번호붙임)
  = 800질의. 첫 실행 14%가 결함 둘(읍·면 키 탈락, 붙임 토큰 미분리)을
  캤고, 수정 후 800/800 = 100.0% (exact 600 / partial 199 / trigram 1).
- 하니스 스크립트와 케이스는 재현 가능하게 보관 (learning_log 2026-07-12).

## 3. 실세계 대조 — 정부 서비스 3~5건

- 데이터/지오코딩 산출물은 **실제 정부 서비스와 3~5건 교차 대조**한다.
  좌표는 실위치와, 주소는 공식 표기와 맞춰본다.
- 선례: 서울시청·서울역·국회·경복궁·하남시청 5건 전부 좌표 정확 확인.
  **검증 케이스의 정답부터 검증하라** — "여의대로 1"로 국회를 찾다 실패했으나
  주소 자체가 틀렸다(정답은 의사당대로 1).

## 4. 멱등 재실행

- ETL·백필은 **재실행 시 행수 불변**을 확인한다 (upsert/delete+insert의
  트랜잭션 경계, 중복 키 처리). "카운트만 확인"은 금지 (지시서).
- 적재 검증은 3중: 행수=원본 대조 + 표본 실세계 대조 + 멱등 재실행.
  rows=정확히 1,000,000이면 잘린 파일 신호 — 후속 조각 존재를 확인한다.

## 5. 성능 전후 수치

- 성능 개선/회귀 우려가 있으면 **EXPLAIN ANALYZE 또는 프로파일 전후 수치**를
  기록한다 (112s→4s, 10s→0.16s 형식). 체감·추정 금지.
- 부하 관련은 p95 등 분포로 기록 (Phase 4-5 부하테스트 표준).

## 검증 함정 (재현 신호)

- 서버 재기동 검증은 pgrep으로 PID 확인 — 포트 유령(구버전이 계속 응답,
  하니스 9.5% 미스터리의 진범). 원격 pgrep은 `[t]rain.py`로 자기매치 회피.
- 판정용 grep은 파이프 없이 단독 실행 (`grep|cut && echo OK`는 오탐).
