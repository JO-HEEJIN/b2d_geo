# 메모리 규칙 & 교훈 대장 (모델 무관)

## A. 메모리 운영 규칙

저장 위치: 세션 메모리 디렉터리(사용 중인 도구의 영속 메모리) + 이 파일(repo).
**repo가 원본, 메모리는 포인터** — 모델이 바뀌어도 repo는 남는다.

저장할 것: ① 사용자 위임 범위·선호 (why 포함) ② repo에서 유도 불가능한
프로젝트 사실 (승인 이력, 키 위치, 외부 계정 상태) ③ 재발 방지용 함정.
저장 금지: 코드로 아는 것, git 이력, 일회성 맥락, 평문 시크릿.
갱신 규칙: 같은 주제 중복 생성 금지 — 기존 파일 갱신. 틀린 메모리는 삭제.

현재 유효 메모리 2건: 자율 위임(autonomous-execution-grant — 커밋·푸시 포함,
deploy key 경로), 모델 인수인계 포인터(HANDOFF 필독).

## C. 프로세스 교훈 (수치로 증명된 것)

1. **측정 우선**: 지오코더 하니스 첫 실행 14% → 결함 2건(읍면 키, 붙임 토큰)
   발굴 → 100%. 대표 케이스만 통과한 상태를 완성이라 부르지 말 것.
2. **검수자 분리 + 재검증**: QA가 MED 2건을 잡았고, 동시에 QA의 INFO-1이
   반쯤 틀렸다(set_limit 커넥션 고정 무시). 양방향 검증이 정답률을 만든다.
3. **비용 추정 분리**: 일회성(셋업·전송)과 반복(epoch당) 비용 혼합 → 과대추정
   → 불필요한 충전 요청. 이후 분리 계산으로 교정.
4. **극단 개입의 비단조성**: 오버샘플링 ×20 = +64%, ×50 = −51% (자기 표적
   파괴). 개입 강도에는 사용 가능한 창이 있다 — 논문 §5.3.
5. **성능은 어노테이션 수와 무상관** (Spearman ρ=−0.083): 데이터 늘리기 전에
   경계 명확성부터 — 데이터셋 설계 교훈.
