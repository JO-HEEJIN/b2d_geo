# 최상위 모델 전용 작업 판별 기준 (모델 무관 — "최상위"는 상대 개념)

목적: 사용량이 비싼 최상위 모델과 저렴한 하위 모델 사이에서 작업을 배분하는
기준. 2026-07-05~12 세션(최상위 모델 실사용)의 실례로 검증했다.

## 판별 축: 판단 밀도 (judgment density)

**판단 밀도 = (정답이 없는 결정의 수) / (전체 작업 단계 수).**
사양이 정답을 정의하면 밀도가 낮고, 트레이드오프·해석·모호성 해소가
연속되면 높다. 밀도가 높을수록 최상위 모델에 배정한다.

보조 신호 3개:
- **오판 비용**: 틀린 결정이 하류 작업 전체를 오염시키는가 (스키마·키 설계).
- **맥락 폭**: 결정에 필요한 맥락이 여러 시스템에 걸치는가 (데이터 명세 +
  DB 관례 + 지시서 원칙을 동시에 들고 있어야 하는가).
- **검증 가능성**: 산출물을 기계적으로 검증할 수 있으면 하위 모델 + 검수로
  충분하다. 검증 자체가 판단이면 최상위.

## 이 세션 실례 — 최상위 모델이어야 했던 것

| 작업 | 근거 |
|---|---|
| 주소 파서 상태기계 설계 | '가' 계열 법정동 vs '로' 접미 충돌, 행정동/법정동 구분 등 정답 없는 규칙 연속 |
| 3단 폴백 사다리 설계 | 단계 순서·ambiguous 처리·단정 금지 원칙의 절충 |
| 정확도 14% 진단 | 읍·면 키 탈락 가설 수립 — 증상에서 원인으로의 도약 |
| 비단조 오버샘플링 해석 | ×20 성공/×50 붕괴를 암기 가설로 통합, ablation 한계 명시 |
| QA 보고 재검증 | 검수자의 INFO-1(set_limit)이 반쯤 틀림을 판별 — 검증의 검증 |
| 예산-스케줄 재설계 | mAP 손실 vs 비용 vs 시간 3중 트레이드오프 (30→10 epochs) |

## 하위 모델로 충분했던 것 (사양이 정답을 정의)

| 작업 | 근거 |
|---|---|
| 초성 백필 (272만 행) | 입출력 명확, 멱등, 카운트로 기계 검증 |
| Phase 4 미들웨어 | 지시서 6절이 사양 — 구현 자체는 정형 (에이전트가 5/5 검증까지 완수) |
| 문서 정리·todo 갱신 | 형식 반복 |
| dataspec 표 작성 | 실측값 받아쓰기 (측정 설계는 상위, 기록은 하위) |

## 운영 규칙

1. 작업 착수 전 판단 밀도를 한 줄로 평가해 배정을 명시한다.
2. 하위 모델 산출물은 반드시 독립 검수를 거친다 (VERIFIER_SUBAGENT_SPEC.md).
3. 경계 사례는 최상위가 설계 문서를 쓰고 하위가 구현한다 — 이 세션의
   "파서 설계문서(상위) → 구현은 문서대로" 패턴이 원형.
