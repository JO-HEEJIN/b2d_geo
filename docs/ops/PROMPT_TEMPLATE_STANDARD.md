# 위임 프롬프트 표준 (PROMPT TEMPLATE STANDARD — 모델 무관)

목적: 서브에이전트·작업 위임 프롬프트의 골격. 약한 완료 기준("잘 되게")은
매번 재확인을 부르고, 강한 기준(수치)은 독립 루프를 가능하게 한다
(전역 CLAUDE.md §4). 모든 위임은 아래 4요소를 채운다.

## 4요소 (필수)

1. **목표** — 한 줄. 무엇을 만드는가. 한 위임에 한 목표.
2. **완료 기준 (수치)** — 기계로 검증 가능한 조건. "하니스 N건 통과",
   "행수=원본", "EXPLAIN < Xs", "테스트 K개 green". 수치가 없으면 위임하지
   않는다 (TEST_AND_VERIFICATION_STANDARD).
3. **제약** — 기존 관례 우선(grep으로 확인), 신규 의존성 금지, 변경 줄
   전부 요청 소급, 건드리면 안 되는 파일·경계 (CODE_WORKFLOW_RULES §5).
4. **보고 형식** — 무엇을 어떤 순서로 돌려받을지. 경로는 절대경로, 검증
   수치 병기, 실패·미해결 정직 명기.

## 기본 템플릿 (작업 위임)

> **목표**: [한 줄].
> **완료 기준**: [수치 검증 — 하니스/행수/EXPLAIN/테스트].
> **제약**: 기존 관례 우선(grep 확인), 신규 의존성 금지, 변경 줄 전부
> 요청 소급, [건드리면 안 되는 파일]. build+vet+test 게이트 통과.
> **보고**: 산출 파일 절대경로 + 검증 수치 + 미해결 항목. 끝나면 그것만.

## 변형 A — 검수 요청 (생성/검증 분리)

> [커밋 해시 / working tree diff 범위]를 **독립 검수**. VERIFIER_SUBAGENT_
> SPEC 관점 체크리스트 적용, **원본 데이터에서 재계산**해 산출물과 대조,
> 실 DB(docker exec b2d_postgis psql -U b2d -d b2d_geo)·실호출 대조 허용.
> **코드 수정·커밋 금지**, 메인 동시 작업 파일 접촉 금지. 심각도별 보고
> (CRITICAL/HIGH/MED/LOW/INFO) + PASS 항목 확인 방법 + 미검증 범위 명시.

## 변형 B — 인수인계 (세션·모델 교체)

> POST_FABLE_HANDOFF를 우선 읽고 시작. tasks/todo.md가 작업 단일 진실.
> **목표**: [이어받을 Phase/항목]. **완료 기준**: [해당 항목 검증 수치].
> **제약**: 절대 규칙(데이터 화이트리스트/감정평가 경계/git author/생성·검증
> 분리) 상속, 자율 위임 범위 유효(가역 작업 실행 후 보고). **보고**: 갱신한
> HANDOFF·todo·learning_log 경로 + 이번에 닫은 항목 + 남은 우선순위.

## 작성 규칙

- 위임 전 **판단 밀도를 한 줄로 평가**해 배정을 정한다 (FABLE_ONLY_TASKS).
  경계 사례는 상위가 설계 문서를 쓰고 하위가 구현한다.
- 프롬프트에 정답이 있는 사양을 다 넣으면 하위 모델로 충분하다. 트레이드오프
  해소가 연속이면 나눠서 위임하지 말고 상위가 직접 한다.
