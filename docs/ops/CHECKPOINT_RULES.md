# 장기 작업 체크포인트 규칙 (모델 무관)

적용 대상: 시간이 수 시간~수 일 걸리고, 실패 시 돈·시간이 날아가는 작업
(원격 학습, 대량 적재, 대량 전송). 근거는 2026-07 세션 실례.

## 규칙 1 — 회수 전 종료 금지 (최우선)

원격 볼륨은 인스턴스와 함께 소멸한다. 종료 절차는 항상:
산출물 회수 → **양쪽 md5 대조** → 대조 일치 확인 → 그 다음 종료.
실례: RunPod pod 2개 모두 best 체크포인트·로그·평가로그 회수와 md5 일치
확인 후에만 podTerminate. 순서를 바꾼 적이 한 번도 없어야 한다.

## 규칙 2 — 중간 보험 회수

작업이 끝나기 전에도 "지금 죽으면 아까운" 시점마다 중간 산출물을 회수한다.
실례: 2차 학습 잔액 마진이 $0.57로 얇아지자 epoch 7 시점에 best_stg1+last를
선회수 — 이후 잔액 사고가 나도 epoch 6까지의 성과는 로컬에 안전한 상태를
만들고 계속 진행했다.

## 규칙 3 — 중단 임계는 사전에 수치로

위기 순간에 판단하지 말고, 시작 전에 숫자로 박아둔다.
실례: "epoch 8 완료 시점 잔액 $1.5 미만이면 조기 중단 (no-aug 1 epoch
확보 상태라 성과 대부분 보존)" — 이 규칙이 있어서 잔액 감시 이벤트가
와도 즉시 기계적으로 판정 가능했다.

## 규칙 4 — 재개 가능성은 멱등으로 확보

체크포인트의 반쪽은 "다시 돌려도 안전한 코드"다.
실례: 지적도 적재가 스트림 사망으로 부분 적재됐을 때, PNU upsert 멱등
설계라 실패 조각만 재전송·재실행으로 복구. 삭제+재삽입(월 단위 실거래)도
같은 원리. 신규 장기 작업은 설계 시점에 "중간에 죽으면?"을 답해야 한다.

## 규칙 5 — 진행 감시는 이상 신호만

체크포인트 간격의 감시는 "정상 진행 로그"가 아니라 이상 신호(크래시 패턴,
잔액 임계, 정체)만 알리게 설계한다. 실례: 2분 간격 전송 진행률 알림을
정체/완료 전용 감시로 교체 — 노이즈 제거 + 판정 자동화.

## 체크리스트 (장기 작업 시작 전)

- [ ] 중간 산출물 회수 시점·방법 정의됨
- [ ] 중단 임계 수치 박제됨 (돈·시간·품질)
- [ ] 재실행 멱등성 확인됨
- [ ] 종료 절차에 회수→md5→종료 순서 명시됨
