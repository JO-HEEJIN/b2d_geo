# 다단계 자동화 SOP (MULTI-STAGE WORKFLOW — 모델 무관)

목적: 장시간·다단계 자율 작업(대형 적재, 원격 학습, 순차 파이프라인)의
운영 표준. 원칙: 대기는 폴링이 아니라 이벤트로, 감시는 이상 신호만, 판정은
사전 수치로 (SYSTEM_PROMPT_V2 §7). 검증은 TEST_AND_VERIFICATION_STANDARD.

## 1. 착수 전 — 판정 임계 사전 수치화

- 각 단계의 **성공/실패/중단 조건을 착수 전에 수치로 박아둔다**. "잘 되면
  진행"이 아니라 "epoch 3에서 val mAP < 0.03이면 중단" 식으로.
- 예산·시간 상한을 명시 (시간당 단가 × 실측 처리량으로 총액, 일회성 비용
  분리). 상한에 닿는 결정만 사용자 확인, 나머지는 실행 후 보고.

## 2. 대기 — 이벤트 기반

- 완료를 **완료 통지로 안다** (프로세스 종료 훅, 로그 마커). 고정 간격
  sleep 폴링 금지 — 늦거나 이르게 깬다.
- 조건 대기는 "그 조건이 참일 때까지"의 감시 루프로 (Monitor 계열).
  단순 시간 지연을 sleep로 만들지 않는다.

## 3. 감시 — 이상 신호만

- 감시는 **정상은 조용, 이상만 알리게** 설계한다. 로그 전량 스트리밍이
  아니라 임계 위반·중단 조건 발동·완료만 깨운다.
- 지표 저하의 원인은 필드로 먼저 분리한다 (GPU util 저하 시 data 시간
  필드로 IO/CPU 구분 — MooseFS 병목 오진 선례). 컨테이너 자원은
  nproc/free(호스트 수치)가 아니라 cgroup(cpu.max, memory.max)을 본다.

## 4. 병렬 스트림 — 이중 검증

- 병렬 전송/처리는 **완료 에코 수 < 스트림 수면 조용한 사망**. 에코 카운트와
  원격 정산(원격에서 실제 행수/파일수 재확인)을 둘 다 본다.
- macOS 도구 함정: unzip이 정상 zip도 깸(Python zipfile 사용), rsync
  2.6.9는 bg에서 실패를 성공으로 오인 → 전송 후 원격 카운트로 검증.

## 5. 완료 시퀀스 (순서 고정)

각 단계·세션 종료 시 아래를 순서대로:

1. **검증** — 산출물을 하니스/대조로 확인 (수치 확보).
2. **회수** — 원격 산출물을 로컬로 내리고 **체크섬(md5) 대조**. 원격
   볼륨은 인스턴스와 함께 소멸하므로 종료 전 반드시.
3. **정리** — 켜둔 감시·서버·과금 자원(인스턴스·pod)을 목록화해 종료.
4. **기록** — learning_log에 사건 서사(원인→조치→교훈), 함정은 재현 신호와.
5. **보고** — 결론 선행 종합 보고 (FINAL_RESPONSE_STYLE_GUIDE).

## 셸 함정 (자동화 스크립트)

- 판정용 grep은 파이프 없이 단독 (`grep|cut && echo OK` 오탐). 원격 pgrep은
  `[t]rain.py`로 자기매치 회피. zsh 단어 분리는 `${=var}` 명시.
