# 자동 작업 종료 판정 규칙 (모델 무관)

문제: 자율 세션에서 "끝났다"는 선언이 가장 오염되기 쉬운 보고다.
실례: 사용자가 "끝났다고? 전부다?"라고 되물은 사건 — "오늘 계획분 완료"와
"프로젝트 완료"를 구분하지 않으면 신뢰가 깎인다.

## 완료의 3요소 (하나라도 없으면 완료 선언 금지)

1. **검증 수치** — 하니스 결과(800/800), 실호출 응답, 행수 대조 등
   제3자가 재현 가능한 숫자. "동작함"은 수치가 아니다.
2. **영속화** — 커밋 해시(+푸시). 커밋 안 된 완료는 완료가 아니다.
3. **보고** — 사용자에게 수치·해시·남은 것을 함께 전달. 남은 것이 0인
   보고는 오히려 의심 신호 — 정직한 완료 보고에는 보통 "잔여" 절이 있다.

## 종료 vs 대기 — 반드시 구분해 선언

- **대기 상태**: 예약된 트리거(학습 완주, 적재 완료, 외부 승인)가 남아
  있고 그 이벤트가 자동으로 나를 깨우는 상태. 선언 형식:
  "대기 중 — 예약 큐: [이벤트 → 후속 절차]". 이것은 종료가 아니다.
- **예약 큐 소진**: 걸어둔 트리거가 전부 소비되고 자동으로 깨어날 일이
  없는 상태. 이때만 "대기 작업 없음"을 선언한다.
- 실례: "완주하면 시퀀스 진행하고 보고해줘" 위임 후 — 학습 4시간 대기는
  종료가 아니라 대기였고, 완주 이벤트 → 평가→회수→종료→분석→푸시→보고
  시퀀스가 소진된 뒤에야 종료를 선언했다.

## 범위 한정 완료 문법

완료 선언은 항상 분모를 붙인다:
- "오늘 계획분(Phase 2·3·4 코어) = 완료. 프로젝트 전체 = 미완 —
  잔여: [목록]" — 실제 사용한 문장 구조.
- 단위: 이번 지시 / 오늘 큐 / Phase / 프로젝트. 어느 분모인지 명시.

## 종료 직전 점검 (자원 누수 방지)

- 켜둔 것 전수 나열: 감시 태스크, 로컬 서버, 원격 인스턴스, 과금 자원
- 각각 "유지 이유" 또는 "정리함" 중 하나로 처분
- 실례: YOLO 감시 모니터는 완주 처리 직후 명시적으로 TaskStop — 임무가
  끝난 감시를 살려두면 다음 세션에 유령 이벤트를 만든다.
