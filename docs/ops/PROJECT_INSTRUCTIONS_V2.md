## 확립된 운영 관례 (이번 세션 성문화)

### 데이터 작업
- 적재 전 `docs/dataspec/<이름>.md` 실측 명세 필수 (좌표계 bbox 실측,
  인코딩 디코드 시험, 스키마 헤더 파싱, 함정 명기). 기존 5종 참조.
- 적재 후 3중 대조: 행수=원본, 표본 실세계 대조(실주소·실필지),
  멱등 재실행. "카운트만 확인" 금지 (지시서).
- 정규화 키 관례: 어절 단일 공백 결합 (buildings.norm_road 기준).
  신규 로더는 기존 관례를 먼저 grep으로 확인하고 맞춘다.

### 코드 작업
- 신규 쿼리는 2.7M~13M 행 테이블 기준 EXPLAIN 실측 후 반영
  (pg_trgm 기본 임계 0.3 금지 — set_limit 커넥션 고정 패턴 사용).
- 미들웨어 순서: IP 제한(최외곽) → 인증 → 키 제한 → 계측 → 핸들러.
- 에러 응답에 내부 정보·키 노출 금지 (업스트림 에러는 redact 후 로그만).

### 검증 관례
- 기능 완성 선언 = 하니스 수치 (지오코더 800/800 선례).
- 서버 재기동 검증은 pgrep으로 PID 확인 (포트 유령 선례).
- 정부 서비스 교차 대조는 실물 3~5건 (하남시청·서울시청 선례).

### 기록 관례
- learning_log.md: 사건 단위 서사 (원인→조치→교훈), 커밋 해시 참조.
- tasks/todo.md: 완료 체크에 검증 근거 1줄 병기.
- 알려진 이슈는 발견 즉시 todo의 해당 Phase 감사 항목에 명기.

### 자원·비용
- GPU/클라우드: 시간당 단가 × 실측 처리량으로 총액 추정, 일회성 비용 분리.
- 원격 볼륨은 인스턴스와 함께 소멸 — 종료 전 회수+체크섬.
- API 키는 .env 전용 (gitignore 확인 후 기록), 채팅·커밋에 평문 금지.
