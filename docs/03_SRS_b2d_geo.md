## 1. 서론

### 1.1 목적
b2d_geo v1의 기능/비기능 요구사항을 정의하고, 테스트 케이스(05 문서)와
추적 가능한 요구사항 ID를 부여한다.

### 1.2 용어
| 용어 | 정의 |
|---|---|
| PNU | 필지고유번호 (19자리). 법정동코드(10) + 대장구분(1) + 본번(4) + 부번(4) |
| bcode | 법정동코드 10자리 |
| 정규화 주소 | 공백/약어/표기 변형을 통일한 매칭용 내부 표현 |
| 자모 분해 | 한글 음절을 초성/중성/종성으로 분해한 문자열 (부분 일치 검색용) |
| 배치 | POST 단일 요청에 다건 쿼리를 담는 처리 방식 |

### 1.3 시스템 범위
02 문서 컴포넌트 다이어그램의 ETL(b2d-etl)과 API 서버(b2d-server) 전체.
지도 렌더링, 길찾기, 웹 콘솔, 결제 연동은 범위 외 (SDP 1.3).

## 2. 기능 요구사항 (FR)

### 2.1 ETL

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | b2d-etl은 juso.go.kr 주소 DB(건물정보)와 위치정보 DB를 다운로드, EUC-KR을 UTF-8로 변환, 구분자 기반 파싱 후 buildings 테이블에 적재해야 한다 | 필수 |
| FR-02 | b2d-etl은 data.go.kr 상가(상권)정보 CSV(UTF-8, 콤마 구분)를 places 테이블에 적재해야 한다 | 필수 |
| FR-03 | b2d-etl은 국가공간정보포털 연속지적도와 법정동 경계를 parcels, admin_areas 테이블에 적재해야 한다 | 필수 |
| FR-04 | 모든 원본 좌표는 적재 시 EPSG:4326으로 변환되어야 하며, 변환은 PostGIS ST_Transform으로 수행한다 | 필수 |
| FR-05 | 적재 전 스키마 검증(컬럼 수, 타입, 좌표 범위: 한반도 bbox)을 수행하고, 불일치 시 적재를 중단하고 원인을 보고해야 한다 | 필수 |
| FR-06 | 모든 레코드는 source(출처)와 source_version(원본 버전 일자)을 보존해야 한다 | 필수 |
| FR-07 | 월간/분기 변동분 갱신을 지원해야 한다 (전체 재적재 아닌 upsert) | 권장 |

### 2.2 주소 파서 (internal/address)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-10 | 파서는 도로명주소와 지번주소를 구분하여 구조화(시도/시군구/읍면동/도로명/건물번호/지번)해야 한다 | 필수 |
| FR-11 | 파서는 다음 변형을 처리해야 한다: 시도 축약(경기/경기도, 서울/서울시/서울특별시), 동 표기 변형(일동/1동), 산 지번, 괄호 병기, 건물번호 본번-부번 | 필수 |
| FR-12 | 정규화기는 공백 제거, 자모 분해, 특수문자 제거를 제공해야 한다 | 필수 |

### 2.3 Geocoding

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-20 | GET /v1/geocode?query= 는 3단 폴백(정확 일치 → 정규화 일치 → trigram 유사도)으로 후보를 반환해야 한다 | 필수 |
| FR-21 | 각 후보는 road_address, jibun_address, lat, lng, building_name, pnu, bcode, score를 포함해야 한다 | 필수 |
| FR-22 | score는 정확 일치 1.0, 정규화 일치 0.9, trigram 폴백은 similarity 값을 사용하며 내림차순 정렬되어야 한다 | 필수 |
| FR-23 | POST /v1/geocode/batch 는 요청당 최대 10,000건을 처리하고, 건별 성공/실패를 개별 반환해야 한다 (부분 실패 허용) | 필수 |
| FR-24 | 동일 정규화 쿼리는 in-memory LRU 캐시에서 응답할 수 있어야 한다 | 권장 |

### 2.4 Reverse Geocoding

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-30 | GET /v1/reverse?lat=&lng= 는 최근접 건물(KNN)의 주소와 좌표가 속한 법정동(ST_Contains)을 함께 반환해야 한다 | 필수 |
| FR-31 | 최근접 건물이 반경 500m 내에 없으면 건물 필드는 null, 행정구역만 반환해야 한다 | 필수 |
| FR-32 | 응답에 해당 지점의 PNU를 포함해야 한다 (parcels 조인) | 필수 |

### 2.5 Places / Keyword

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-40 | GET /v1/places/search 는 query(상호명), lat/lng/radius(선택), category(선택) 조합 검색을 지원해야 한다 | 필수 |
| FR-41 | 상호명 매칭은 자모 분해 정규화 + pg_trgm으로 부분/오타 일치를 지원해야 한다 | 필수 |
| FR-42 | GET /v1/places/category 는 업종코드와 bbox로 목록을 반환해야 한다 | 필수 |
| FR-43 | 초성 검색(예: "ㅇㄱ" → 약국)은 Phase 5 범위로 한다 | 선택 |

### 2.6 Parcel (부동산 특화)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-50 | GET /v1/parcel?pnu= 는 필지 속성과 폴리곤(GeoJSON)을 반환해야 한다 | 필수 |
| FR-51 | GET /v1/parcel/by-address?query= 는 주소를 PNU로 매핑해야 한다 (geocoding 파이프라인 재사용) | 필수 |
| FR-52 | GET /v1/parcel/at?lat=&lng= 는 좌표를 포함하는 필지를 반환해야 한다 | 필수 |

### 2.7 인증 / 계측 / 운영

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-60 | 모든 /v1/* 엔드포인트(health 제외)는 Authorization: Bearer 헤더의 API key를 요구해야 한다 | 필수 |
| FR-61 | API key는 SHA-256 해시로만 저장하고, 식별용 prefix(앞 8자)만 평문 보관한다 | 필수 |
| FR-62 | rate limit은 key별 token bucket으로 적용하며 초과 시 429를 반환해야 한다 | 필수 |
| FR-63 | 사용량 계측은 요청 경로를 blocking하지 않아야 한다 (채널 + 배치 insert) | 필수 |
| FR-64 | GET /v1/usage 는 해당 key의 기간별 엔드포인트별 호출량을 반환해야 한다 | 필수 |
| FR-65 | GET /v1/health 는 인증 없이 DB 연결 상태를 반환해야 한다 | 필수 |
| FR-66 | 에러 응답은 {"error":{"code","message"}} 형식으로 통일하고 내부 정보(스택, 쿼리문)를 노출하지 않아야 한다 | 필수 |

## 3. 비기능 요구사항 (NFR)

| ID | 분류 | 요구사항 | 측정 기준 |
|---|---|---|---|
| NFR-01 | 성능 | 단건 geocode p95 latency < 50ms (캐시 미스, 로컬 DB 기준) | Phase 4 부하 테스트 |
| NFR-02 | 성능 | 배치 geocode 10,000건 < 60초 | Phase 4 부하 테스트 |
| NFR-03 | 성능 | reverse geocode p95 < 30ms (KNN + ST_Contains) | Phase 4 부하 테스트 |
| NFR-04 | 정확도 | 실주소 200건 테스트 셋에서 geocoding 1순위 정답률 >= 90% | Phase 2 exit criteria |
| NFR-05 | 가용성 | SaaS 월 가용성 99.5% 목표 (1인 운영 현실 반영, SLA 명문화는 계약별) | 운영 모니터링 |
| NFR-06 | 보안 | SQL 전량 파라미터 바인딩, 문자열 조합 쿼리 0건 | b2d-qa 전수 감사 |
| NFR-07 | 보안 | govulncheck CI 통과, 알려진 취약점 0건 상태로만 릴리스 | CI 게이트 |
| NFR-08 | 이식성 | 온프레미스 패키지는 외부 네트워크 통신 0건으로 동작해야 한다 | 오프라인 환경 E2E |
| NFR-09 | 유지보수성 | 프로덕션 바이너리 직접 의존성 5개 이하 | go.mod 검사 |
| NFR-10 | 준법 | 서빙 데이터의 100%가 허용 목록(공공데이터) 출처여야 하며 provenance로 증명 가능해야 한다 | source 필드 전수 검사 |

## 4. 외부 인터페이스 요구사항

- 입력 데이터 인터페이스: juso.go.kr(파일 다운로드, EUC-KR/구분자 |), data.go.kr
  상가(상권)정보(CSV/UTF-8/콤마), 국가공간정보포털(shapefile). 포맷 변경은 R-02로 관리.
- 제공 인터페이스: HTTP/JSON, OpenAPI 3.1 스펙(D-05)이 단일 진실 원천.
- 좌표계: 입력/출력 모두 WGS84(EPSG:4326). 내부 저장도 4326으로 통일.

## 5. 제약사항
- 언어/스택: Go 1.23+, net/http, PostgreSQL 16 + PostGIS 3.4, pgx/v5 (SDP 2.2, 실행 지시서 4절).
- 상용 서비스(네이버/카카오/구글) 유래 데이터 및 크롤러 코드 작성 금지 (R-01, NFR-10).
- OSM(ODbL) 데이터는 v1에서 사용 보류 (R-06).
