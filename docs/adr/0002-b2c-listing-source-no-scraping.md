# 0002. B2C 남은 매물은 계약 피드와 직접 등록만 원천으로 쓴다

## Context

2026-11 B2C 모듈 5(남은 매물)를 만들었다. 매물이 빠르게 거래되므로 지금 남은 매물을
보여줘야 했고, 네이버 부동산이 이를 실시간으로 제공하고 있었다. 가장 빠른 길은 포털
매물을 주기적으로 긁어오는 것이었다. 그러나 최상위 지시서 1.1은 상용 서비스 스크레이핑과
크롤러 코드 작성을 금지했다. 올맵은 상업 판매용이라 데이터베이스권 침해 위험을 원천
차단해야 했다.

## Decision

- 포털 스크레이핑을 기각했다.
- `ListingSource` 인터페이스 뒤에 이용 계약이 있는 매물 피드, 또는 중개사·집주인이 직접
  등록한 매물만 둔다. 모든 매물에 `Source`를 남긴다.
- 갱신은 cron이 아니라 systemd 타이머(`OnCalendar=*:*:00`, `Persistent=true`)가 oneshot
  서비스를 매분 실행하는 방식으로 했다. 상태는 실행 사이에 JSON 파일로 잇는다.

## Consequences

- 법적 위험 없이 상용 판매할 수 있다. 대신 첫 매물 원천을 확보하기 전까지 모듈 5는 실제
  매물을 보여주지 못한다. 매물 수에서 네이버를 따라잡는 데 시간이 걸린다.
- 타이머 덕분에 서버 재기동 뒤 놓친 갱신을 바로 따라잡고, 실행 기록이 journalctl에 남는다.
- 지켜볼 것: 원천의 호출 한도가 매분 주기를 감당하는지, 상태 파일이 커지는 속도.
